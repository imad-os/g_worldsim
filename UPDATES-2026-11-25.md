## 1. Before you use it: setup on the PC

The panel on GitHub Pages is always the newest code. The server on the PC must run the same code, or the panel shows a red
"server runs older code" banner.

- **Update once by hand** (a server older than today cannot update itself):
  `powershell -File tools\restart.ps1 -Pull` in `D:\frb\g_worldsim`. It pauses the watchdog, stops the server cleanly,
  pulls, starts it hidden and waits for `/health`. Node: `D:\node\node.exe`, else `.node\`, else PATH.
- **After that, pull + start is enough**: `npm start` checks itself at start (`fresh.ts`): package files newer than
  `node_modules` = `npm install`, sources newer than the last build = rebuild. `WORLDSIM_NO_AUTOBUILD=1` turns that off.
- **From then on the panel can do it**: Server page > Update from GitHub / Rebuild / Restart (see 2).
- **To-do page token**: make a GitHub fine-grained token for `imad-os/g_worldsim` with *Issues: read and write*, paste it on
  the To-do for Claude page. It stays in that browser only (never sent to the world server).
- **AI brains**: Gemini keys can go in `.env` as `GEMINI_API_KEYS=k1,k2` (they take turns), or in a brain's key field in
  the panel. `OPENAI_API_KEY` works for OpenAI-compatible brains. The Ollama address stays only on the PC, never in the repo.
- **Firebase owner email**: only in the rules copy published in the Firebase console (`firebase/firestore.rules` keeps a
  placeholder).

## 2. Server and control panel

**Server page** (owner): commit and local changes, process id, database size, the running job, the server log, and buttons:
- *Restart*: clean stop, the same command starts again (the watchdog is paused meanwhile).
- *Rebuild* and *Update from GitHub*: `git pull --rebase` (agent commits ride on top; a conflict aborts and says so),
  `npm install` if needed, build, restart.
- *Backups*: make, restore (applied at the next start, the old database kept), delete; the last 15 are kept.

**Errors page**: every server warning, error and crash in one list (SQLite, last 3000, repeats counted instead of
duplicated), filter by source / level / text, a badge in the menu, live notices. Failed admin commands land there too.

**Clear "old server" message**: the server now tells the panel its build and its list of commands. A command the server does
not know is refused at once with a plain explanation and a red banner, instead of "unknown command".

**Person editor in percent**: Food / Water / Rest / Company / Health / traits are shown and edited as 0-100 %.
**No hard limits**: a value outside the usual range asks "are you sure?" and is applied on yes, instead of being refused
(only what the engine cannot hold, such as negative ids or hours, stays refused).

**Analysis page** (staff): every world stat in one place: population, why each woman 18+ has no baby right now, single men
and women and possible pairs, objectives done / failed with the top failure reasons, per map animals / trees / rocks /
farms / huts / doors / beds / leader, what people are doing, deaths, clans, rules, AI use.
*Ask the AI*: type a question, tick which logs to include (people, life, work, danger, social, conversations, travel,
admin, AI, server errors), pick a brain, preview the prompt, send. Answers are kept (last 30).

## 3. AI brains and the panel's AI agent

**Brain stats and fallback**: every AI call is counted per brain (calls, errors, last 24 h, 7 days, lifetime) on the AI
brain card. Choose a *fallback brain*: when the brain in use fails 3 calls in a row, the fallback thinks for 30 minutes,
then the main one is tried again.

**AI agent page** (owner only): ask in words ("why is Lina always hungry?", "give everyone an axe", "make wolves rarer").
The agent can look freely (read files, search code, read-only SQL, read a copy of the world), then **proposes**:
- *Run*: a short script in the live server. Nothing happens until you press Run. A backup and a snapshot are taken first.
- *Apply*: a code edit. Originals are kept, the server is rebuilt (a failed build puts them back), and each applied edit is a
  local git commit ("World agent #id: ...").
- *Revert*: runs are undone by restoring the backup; edits by `git revert` + rebuild + restart.
Everything is audited. Keys and tokens are shown as `***`. The agent uses its own brain setting, not the people's budget.
Note: agent commits stay on the PC; bring them into the repo by hand if you want to keep them.

## 4. Smarter people (local AI research)

Started with an audit of how people decide (`research/ARCHITECTURE.md`), then measured every change with a repeatable
experiment harness (`npm run experiment -- --days 3 --arms old,new`; results in `research/EXPERIMENTS.md`).

**Camp planning (GOAP)**: instead of a fixed list of chores, each camp has drives (warmth, food, shelter, defence, tools...)
that become goals; goals go to the best-suited free person (traits x chance of success x time); a planner works out the
steps from the recipe table (e.g. no axe -> gather wood + stone -> craft axe -> chop). People **learn** from outcomes (what
works for them and for their camp) and back off from goals that keep failing. **Siting**: the camp, huts and the wall are
placed by rules (reachable doors, inside the wall circle, no two builders on one tile), and the wall circle is sized to the
village.

Measured (5 people, 3 game days, 5 seeds): task success **0.63 -> 0.99**, repeated failure loops **5.2 -> 0**, working huts
**8/15 -> 14/15**, wall finished in every run, fire burning **40 -> 64** of 72 hours, same CPU cost.

**Instincts** (after your report "they don't defend themselves / say they'll do it but stand"):
- Fight or flight by the real odds (health, damage, friends within 14 m, courage, protecting family), alarm shouts that wake
  people nearby, no fleeing into a hut the threat is already in.
- Hunters stalk and search farther; at dusk people drink and eat, at night they go home when zombies walk.
- Requests from chat ("make a sword", "build a hut") are planned for real, or the person says honestly why not.
- **Memory**: 10 recent, 100 long-term memories and remembered places, written into every prompt about the person.
Defence test: deaths against a bear / zombies went down sharply (E7, E8: deaths per run 2.7 -> 0.3).

## 5. Strict rules both ways

Your rules were all "must" rules and only the first one worked. Now:
- **Must** rules ("you must hunt every day", "chop wood every morning", "never forget to feed the fire") become recurring
  work: every hour / N hours / day / week, twice a day, morning / afternoon / evening / night. Understood in en / fr / es / ar.
- **Never** rules ("you never talk to Miceal", "never hunt") block, as before.
- Misspelt names are matched (one or two letters off); an unknown name blocks nobody.
- Rule work pushes aside the person's own plans, never your or a player's orders.
- Panel (Strict rules card and the person's Rules tab) shows **how each rule was understood** and how often it was kept
  or failed, with the reason.

## 6. Homes, building, resources

- **Homes**: a hut gets an owner (its builder, else a household that has none, couples with children first). Its door opens
  only for the owner, partner, parents, children and siblings; others are stopped at the doorway. People sleep at home and
  flee to a roof whose door opens for them. When an owner dies, the partner or a grown child inherits.
- **Huts come with their own door**; cost is now 14 wood + 4 stone.
- **Aimed building on the TV**: choosing something to build shows a see-through model (green = OK, red = not) that you move
  tile by tile with the stick / arrows; X / Y / shoulders turn a hut's door; A / OK builds exactly there, B cancels.
- **Resources regrow** to a steady level per map: trees on stumps and next to trees, rocks surface out of sight. Never in the
  camp, homes, roads or near portals. Rocks are hard (6 blows), stone 60 %, ore only 10 % per blow.
- Admin can set a bag directly (person Edit tab / `agentSet`).

## 7. Children and family roles

- **Under 3** = little ones: babies (< 1) are carried by their carer, toddlers follow. The carer (mother, father, family,
  else the kindest adult near) feeds them, gives water and puts them to bed. If a player-parent lets a need go too far, an AI
  helper steps in. Parents fight for a child a zombie or beast goes for; one holding a baby runs.
- **Children talk like children** (cries, babble, one word, short sentences), with no AI call for babies.
- **Family roles between players**: on the TV, ask another player to be your child / sibling / parent; they accept on their TV.
  No courting, marriage or child within the family (blood or chosen).
- TV Me > My family: your children's needs, Feed / Give water / Pick up / Put to bed. Panel person Family tab: stage,
  carer, children's needs, chosen family.

## 8. Quests, NPCs and clans

- **5 teachers in the town centre** (not people: no needs, never die): guide Mara, smith Joren, hunter Sela, warden Bram,
  registrar Odile. On the TV they have a cyan ring; Talk to them.
- **10 tutorial quests** in order (drink, pick up, gather, craft, build, tend the fire, hunt, join a clan...). Progress is counted
  from what you really do; hand in to the giver for xp, items and food. AI people take them too, and the lessons go into
  their prompts. TV Quests page; panel Quests cards.
- **Clans**: founded at the registrar (name typed on the TV), joined by asking the leader (an AI leader can refuse someone
  they dislike), quit, switch. **Leaders are elected**: every 3 game days, sooner if approval drops under 35 % or someone
  calls a vote; 2 game hours to vote, players vote on the TV. AI leaders give orders only for real needs (arm and rally at
  night with zombies, food / wood when the store is low); a player leader can give the clan an order in words.
  Panel Clans card: elections, approval, respect.

## 9. Gear, items and moves (graphics)

- **Free 3D models** (CC0: Quaternius, KayKit, Kenney; credits in `docs/models/CREDITS.md`) for sword, axe, spear, bow,
  hammer, sledge, helmet, shoulder pads, plus 27 item icons.
- **Bag & crafting screen** in a Minecraft-like layout: category tabs, 3x3 grid, result slot, recipe book that fills the grid,
  9x4 bag. A on a material = into the grid, on gear = equip, on a block = put it down.
- **Gear screen**: a live 3D preview of your character, 4 slots (weapon, ranged, head, body; Best / Nothing / a choice),
  **Level up** (+0 to +10) and **Raise quality** (normal, fine, superior, epic, elite) with their material costs; they raise
  damage / defence. AI people upgrade what they use up to +3.
- **Seen on people**: weapon in hand, bow on the back, helmet, pads, tunic, quality tints and a glow from superior up.
  **Moves**: attack, chop with an axe, mine with a hammer, build, talk with a nod, shoot.

## 10. Horses

- Wild herds in the woods (not in town): lead mare, stallion guarding the edge, foals with their mother; they graze, doze,
  bunch at night, flee zombies, wolves, bears and people who run at them; the stallion kicks predators. Calm people slowly win
  their trust.
- **Quality**: common, rare (blue glow), legendary (gold ring, golden mane). Each horse has its own size, speed and stamina.
- **Taming is a skill**: chance from courage, intelligence, speed, level, trust and food; failing builds trust but may get you
  kicked. Each try improves your taming level.
- **Riding**: A next to your horse mounts / dismounts (or the Horse action on the wheel); trot, gallop while stamina lasts;
  portal journeys take half the time. AI people ride their horse for long trips. Me page shows your horses.

## 11. Chat for your character

Panel page **Chat** (players too, with a linked character): direct messages with anyone, a **world** channel and your
**clan** channel. People answer orders from far away and write back "Done: ..." or "I couldn't ...: why" when the task ends,
and post news (births, weddings, deaths, alarms, elections). Answers are limited so the AI budget is not drained.
The admin token has no character, so the page says so.

## 13. Fixes: full world, kill counts, deleting players

- **"Add person says ok but nothing happens", animal Now, zombies "no room", TV could not join**: farm berries had filled every
  entity slot. Food on the ground is now capped per map, room is made when needed (farthest food first), and a full world
  says exactly why.
- **Kill counts per person**: animals by kind, zombies, people, duels won; on People cards ("Sort: most kills"), the dead
  table and the person page.
- **Delete a player** (Players & TVs > Delete): backup first, then the character, bag, TV link, account link are removed.
  Characters without a TV (like "name (2)") are listed so leftovers can be deleted. "Unlink TV" is the old revoke.
- Admin token's Me page now explains it is not an account instead of "unknown command".

## 15. Known limits and what is next

- The PC server must be updated once by hand (section 1) before the panel's Update button exists there.
- Proof screenshots and fps were made in the cloud (software graphics, about 7 fps); real fps checks belong on the PC.
- People are still idle about 80 % of waking hours; conversations are short and rare.
- Fleeing can flip to fighting and back when friends arrive (the odds change with distance).
- Agent code commits stay on the PC until brought into the repo by hand.
- Horses live only in the woods: town people need travel opened to reach them (players can always go).
- One camp per map; clan territory is only a home point.
- Missing sounds: deer, wolf howl, sleep, voices, baby, laugh.
- Next (from `research/BACKLOG.md`): perception cache for big worlds, shared plans (two builders on one hut, hunting
  parties), camps learning their own priorities, social goals in planning, smaller walls; then weather and polish.
